# 非模板化章节：阅读页面原型

这份原型只决定内容怎样被组织，不改变当前配色、字体、侧栏和路由。用户确认后，再改页面的数据结构与渲染器。

## 现在的问题

当前每章都必须依次填写：情境、图解、算例、机制、公式、边界。即使内容本身不需要图解或四步算例，作者也必须凑出对应字段。读者因此反复看到相同的页面轮廓，算法像被装进同一套六格模板，而不是从一个未解决的问题里长出来。

新的页面不再预设六个固定栏目。它只保留章节标题、引言、正文、下一章过渡和资料来源。正文由少量可选内容块组成，按这一章的推理顺序排列。

## 页面骨架

```text
章节标题
一句话说明：这一章到底要解决什么

正文目录（从实际小标题自动生成，不再固定成六项）

连续文章
  普通段落
  可选：完整宽度公式
  普通段落
  可选：一个算例或反例
  普通段落
  可选：关系图或数据表
  普通段落

这一章留下的未解决问题
资料来源
上一章 / 下一章
```

公式、例子和图不再各自占据固定的大区块。它们出现在读者正好需要证据的位置。没有必要的组件就不显示，也不留下空壳。

## 三种允许完全不同的章节节奏

### 算法演化章

从一个最直接的做法开始。让它在具体场景里遇到一个问题，再引入第一个算法。接着追问这个算法留下什么问题，让第二个算法出现。`tabular-control` 适合这种写法：实际下一动作 → 策略期望 → 贪心目标 → 最大化偏差。

### 边界判断章

从几个很容易误判的请求开始。每次先让读者作判断，再说明缺少了哪一条证据。`before-rl` 和 `llm-as-rl` 适合这种写法：不是罗列定义，而是连续纠正“为什么这个还不能叫 RL”。

### 系统追踪章

挑一条真实数据，从环境产生、记录、进入回放、组成目标、更新参数，一直追到评估。`rl-systems` 适合这种写法：每一段只解释数据经过一个环节后发生了什么，错误会在哪里被悄悄带入。

这三种节奏只是示例，不是新的三套模板。选择结构的唯一标准是：读者当前卡在哪里，下一段需要解除哪一个障碍。

## `tabular-control` 的阅读顺序原型

1. 先固定同一条转移，指出即时奖励没有争议。
2. 追问下一状态的未来由谁代表。
3. 让 SARSA 作为“按实际下一动作算”的答案出现。
4. 发现一次抽样会抖动，Expected SARSA 因而出现。
5. 把行为探索与目标评价拆开，Q-learning 因而出现。
6. 发现 max 会挑中正误差，Double Q-learning 因而出现。
7. 用同一组数字计算前三种目标，不更换场景。
8. 最后分开两个边界：贪心目标不保证探索安全；表格收敛不等于神经网络收敛。

读完以后，读者不需要背一张四列对比表，也应能从“下一状态按谁来估价”重新推导出四种方法的关系。

## 需要用户确认的变化

- 章节目录改为根据真实小标题生成。
- 图解、算例、公式、边界提示全部变成可选块。
- 正文以连续文章为主，不再强制每章出现同样数量的卡片。
- 当前视觉系统保持不变；若以后要调整版式，另做视觉原型，不与这次写作重构混在一起。
